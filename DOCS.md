## Запуск

### Быстрый старт

Двойной клик по **`start.bat`** — откроет сервер на `http://localhost:8080`.

### Вручную

```bash
cd backend
python main.py
```

Затем открыть в браузере: `http://localhost:8080`

**Требования:** Python 3.10+. Сторонних пакетов не нужно — всё на встроенных модулях.

### Остановка

`Ctrl+C` в терминале.

## Архитектура

```
Браузер                          Бэкенд (Python)
─────────────────────────────    ──────────────────────────
┌─────────────┐   POST /trace    ┌──────────────┐
│  editor.js  │ ─────────────── ▶│  validator   │ ← AST-проверка
│             │                  └──────┬───────┘
│  Пользо-    │   { steps[] }          │ ok
│  ватель     │ ◀─────────────── ┌──────▼───────┐
│  вводит код │                  │   tracer     │ ← sys.settrace
└──────┬──────┘                  └──────────────┘
       │ steps
       ▼
┌──────────────┐
│ animator.js  │ → шарики, Memory, Console, подсветка строк
└──────────────┘
```

**Принцип работы:**

1. Пользователь пишет код в редакторе CodeMirror и нажимает «Запустить»
2. `api.js` отправляет код на `POST /trace`
3. Бэкенд валидирует код через AST-whitelist
4. `tracer.py` выполняет код с `sys.settrace` и собирает снимок состояния перед каждой строкой
5. Массив шагов (`steps[]`) возвращается в браузер
6. `animator.js` воспроизводит шаги: подсвечивает строки, запускает шарики, обновляет панели Memory и Console

## Бэкенд

### `main.py` — HTTP-сервер

Написан на встроенном `http.server` (причина: pip недоступен из-за SOCKS-прокси в среде разработки).

**Маршруты:**

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/` | Отдаёт `frontend/index.html` |
| `GET` | `/health` | `{"status": "ok"}` — проверка работоспособности |
| `GET` | `/js/*`, `/style.css` | Статические файлы фронтенда |
| `POST` | `/trace` | Валидация + трассировка кода |
| `OPTIONS` | `*` | CORS preflight |

**Формат запроса `POST /trace`:**
```json
{ "code": "for i in range(3):\n    print(i)" }
```

**Формат ответа:**
```json
{
  "steps": [
    { "line": 1, "variables": {}, "output": [] },
    { "line": 2, "variables": {"i": 0}, "output": [] },
    { "line": 1, "variables": {"i": 0}, "output": ["0"] }
  ],
  "error": null,
  "truncated": false,
  "total_lines": 2
}
```

---

### `validator.py` — AST-валидатор

Принимает исходный код, разбирает его в AST и проверяет каждый узел по whitelist. Запрещает всё, чего нет в списке разрешённого.

**Разрешённые узлы AST:** присваивание, арифметика, сравнения, булевы операторы, `if/for/while/break/continue/pass/return`, вызовы функций и методов из whitelist, списки, кортежи, словари, множества, срезы, list comprehension, определения функций.

**Явно запрещено (с понятными сообщениями):**

| Конструкция | Сообщение |
|-------------|-----------|
| `import` | Импорт модулей не разрешён |
| `global`, `nonlocal` | Не разрешён |
| `try/except`, `raise` | Не разрешён |
| `with` | Не разрешён |
| `lambda` | Lambda-функции не разрешены |
| `class` | Определение классов не разрешено |
| `async/await` | Async не разрешён |
| `yield` | Не разрешён |
| генераторы | Не разрешены |

**Возврат:** `(True, '')` при успехе или `(False, "сообщение об ошибке")`.

---

### `tracer.py` — Трассировщик

Использует `sys.settrace` для перехвата выполнения Python-кода построчно.

**Ключевые особенности:**

- `sys.settrace` срабатывает **до** выполнения строки (событие `line`). Поэтому снимок шага N содержит состояние переменных **после выполнения строки N-1**. Фронтенд учитывает этот сдвиг через look-ahead логику в `scheduleNextStep`.
- Код выполняется в изолированном namespace с только разрешёнными встроенными функциями.
- `print()` перехватывается: вывод копится в `captured_output[]`.
- Лимит: **300 шагов**. При превышении `truncated: true`.
- После `exec()` добавляется синтетический финальный шаг с итоговым состоянием переменных и вывода (нужен, т.к. `settrace` не фиксирует состояние после последней строки).

**Сериализация значений (`_serialize`):**
- `int`, `float`, `bool`, `None` → как есть
- `str` → обрезается до 200 символов
- `list`, `tuple` → до 30 элементов, рекурсия до глубины 3
- `dict` → до 15 ключей, ключи приводятся к `str`
- `set` → до 15 элементов, сортируется
- Всё остальное → `str(value)[:100]`

### `animator.js` — движок анимации

Главный модуль. Управляет воспроизведением шагов, панелями Memory и Console, и анимацией шариков.

#### Состояние

```javascript
let steps       = [];   // массив шагов от tracer
let currentStep = 0;    // текущий индекс
let isPlaying   = false;
let playTimer   = null; // setTimeout handle
let prevVars    = {};   // переменные предыдущего шага (для вычисления diff)
let prevOutput  = [];   // вывод предыдущего шага
```

#### Константы тайминга

```javascript
const BALL_DELAY    = 200;  // мс: пауза между подсветкой строки и стартом шарика
const BALL_FLY_MS   = 480;  // мс: время полёта (соответствует GSAP duration 0.45s)
const NO_BALL_PAUSE = 250;  // мс: пауза если в этом шаге нет изменений
```

**Скорость воспроизведения** (значение `<select>`) = пауза **после приземления** шарика перед переходом к следующей строке:

| Опция | Пауза после шарика | Итого на шаг |
|-------|-------------------|--------------|
| Медленно | 800 мс | ~1480 мс |
| Нормально | 300 мс | ~980 мс |
| Быстро | 50 мс | ~730 мс |
| Очень быстро | 0 мс | ~680 мс |

#### Ключевые функции

**`renderStep(index, onDone)`**

Отображает конкретный шаг: подсвечивает строку, обновляет Memory и Console, вызывает `onDone()` сразу. Не запускает шарики — это делает `scheduleNextStep`.

**`scheduleNextStep()`**

Главный цикл авто-воспроизведения. Логика look-ahead:

1. Сравнивает `steps[currentStep]` и `steps[currentStep + 1]` — что изменится
2. Через `BALL_DELAY` запускает шарик от **текущей подсвеченной строки** к нужной цели
3. Когда шарик приземляется — обновляет Memory / Console
4. Через `postPause` вызывает `renderStep(next, scheduleNextStep)` — строка N+1 подсвечивается

**Последовательность событий (Normal speed):**

```
t=   0ms  Строка N подсвечивается
t= 200ms  Шарик стартует от строки N  ← строка N ещё горит
t= 680ms  Шарик приземляется → Memory / Console обновляются
t= 980ms  Строка N+1 подсвечивается
```

**`animateBall(fromEl, toEl, color, onComplete)`**

Создаёт DOM-элемент шарика в `#ball-layer` и анимирует через GSAP (`power2.inOut`, 0.45 с). Дополнительно: 3 trail-точки с задержками `i × 0.06` с. Вызывает `onComplete` при приземлении главного шарика.

**`renderMemory(vars, changedKeys)`**

Перестраивает `#memory-body`. Каждая карточка `.var-card` имеет атрибут `data-var-name="имяПеременной"` — по нему `scheduleNextStep` находит конкретную карточку как цель шарика.

**`renderConsole(output, newCount)`**

Добавляет только новые строки в `#console-body`. Всегда держит `#console-anchor` в самом конце — невидимый ghost-элемент, который служит целью шарика (туда, где появится следующая строка вывода).

#### Управление воспроизведением

| Функция | Описание |
|---------|----------|
| `startAnimation(steps, error)` | Инициализирует, запускает авто-воспроизведение |
| `stopAnimation()` | Останавливает (`clearTimeout`) |
| `togglePlay()` | Пауза / воспроизведение |
| `stepNext()` | Ручной шаг вперёд |
| `stepPrev()` | Ручной шаг назад (пересчитывает prevVars) |

**Кнопки:**
- `⏮` — перейти к шагу 0
- `◀` — шаг назад
- `▶ / ⏸` — воспроизведение / пауза
- `▶▶` — шаг вперёд
- `⏭` — перейти к последнему шагу

## Система анимации

### Цели шариков

| Событие | Цвет | Источник | Цель |
|---------|------|----------|------|
| Переменная изменилась | Синий `#4F7EF7` | Текущая подсвеченная строка | `.var-card[data-var-name="X"]` или центр `#memory-panel` (fallback для новой переменной) |
| Появилась строка вывода | Зелёный `#059669` | Текущая подсвеченная строка | `#console-anchor` (конец `#console-body`) |

### Ghost-якорь `#console-anchor`

`<div id="console-anchor" style="height:0">` всегда находится в самом конце `#console-body`. Он восстанавливается после каждого вызова `innerHTML =`. Шарик летит к нему — и ровно туда через `onBallLand` добавляется новая строка вывода.

## API

### `POST /trace`

**Запрос:**
```http
POST http://localhost:8080/trace
Content-Type: application/json

{ "code": "x = 5\nprint(x)" }
```

**Ответ (успех):**
```json
{
  "steps": [
    {
      "line": 1,
      "variables": {},
      "output": []
    },
    {
      "line": 2,
      "variables": { "x": 5 },
      "output": []
    },
    {
      "line": 2,
      "variables": { "x": 5 },
      "output": ["5"],
      "final": true
    }
  ],
  "error": null,
  "truncated": false,
  "total_lines": 2
}
```

**Ответ (ошибка валидации):**
```json
{
  "steps": [],
  "error": {
    "type": "ValidationError",
    "message": "Импорт модулей не разрешён",
    "line": null
  },
  "truncated": false
}
```

**Поля шага:**

| Поле | Тип | Описание |
|------|-----|----------|
| `line` | `int` | Номер строки (1-based), которая будет выполнена следующей |
| `variables` | `object` | Снимок локальных переменных |
| `output` | `string[]` | Накопленный вывод `print()` (все строки с самого начала) |
| `final` | `bool?` | `true` только у синтетического последнего шага |

## Технические решения

### Почему встроенный HTTP-сервер, а не FastAPI

pip недоступен в среде разработки (SOCKS-прокси блокирует установку пакетов). Бэкенд переписан на `http.server`, `json`, `os` — нулевые зависимости.

### Сдвиг sys.settrace (off-by-one)

`sys.settrace` даёт событие `line` **перед** выполнением строки. Это значит: снимок в шаге N содержит переменные, которые были установлены строкой N-1. В фронтенде это решено через **look-ahead**: `scheduleNextStep` сравнивает `steps[N]` и `steps[N+1]`, запускает шарик от **текущей подсвеченной строки** (которая и производит изменения), а панели обновляет при приземлении шарика.

### Синтетический финальный шаг

После `exec()` в namespace могут остаться изменения, которые `settrace` не успел зафиксировать (последняя строка). Поэтому `tracer.py` добавляет дополнительный шаг с финальным состоянием, если оно отличается от последнего записанного. Не добавляется при ошибке или усечении (иначе было бы 301 шаг).

### CP1251 и Windows-терминал

В `log_message` убраны Unicode-символы (стрелки и т.п.) — они вызывали `UnicodeEncodeError` в кодировке CP1251 консоли Windows и крашили обработчик запроса до отправки ответа.

### Ghost-якорь консоли

Цель шарика для Console — `#console-anchor`, нулевой div в конце `#console-body`. Проблема: `innerHTML = ''` уничтожает его. Решение: модульная JS-переменная `const consoleAnchor = document.getElementById('console-anchor')` хранит ссылку на элемент, и все функции очистки (`clearPanelsUI`, `renderConsole`) восстанавливают его через `consoleBody.appendChild(consoleAnchor)`.
