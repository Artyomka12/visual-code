# Visual Code

Интерактивный визуализатор выполнения Python-кода для подготовки к ЕГЭ по информатике в рамках проекта **ЕГЭволюция**.

Проект содержит два режима визуализации:

1. **Classic View** — пошаговая анимация с scope-блоками и шариками данных.
2. **Flow Graph View** (Experimental) — блок-схема программы с анимированными токенами данных.

## Запуск

### Быстрый старт

Двойной клик по **`start.bat`** — откроет сервер на `http://localhost:5000`.

### Вручную

```bash
cd backend
python main.py
```

Затем открыть в браузере: `http://localhost:5000`

**Требования:** Python 3.10+. Сторонних пакетов не нужно — всё на встроенных модулях.

### Остановка

`Ctrl+C` в терминале.

## Архитектура

```
Python Code
     ↓
  Tracer  (backend/tracer.py — sys.settrace)
     ↓
Execution Steps  (steps[]: line / call / return)
     ↓
Visualization Mode
  ├── Classic View    (animator.js)
  └── Flow Graph View (flow-graph.js)
```

```
Браузер                          Бэкенд (Python)
─────────────────────────────    ──────────────────────────
┌─────────────┐   POST /trace    ┌──────────────┐
│  editor.js  │ ─────────────── ▶│  validator   │ ← AST-проверка
│             │                  └──────┬───────┘
│  Пользо-    │   { steps[] }          │ ok
│  ватель     │ ◀─────────────── ┌──────▼───────┐
│  вводит код │                  │   tracer     │ ← sys.settrace
└──────┬──────┘                  └──────────────┘
       │ steps
       ▼
┌──────────────────────────────┐
│   Режим визуализации         │
│  ┌────────────┐ ┌──────────┐ │
│  │animator.js │ │flow-graph│ │
│  │ (Classic)  │ │  .js     │ │
│  └────────────┘ └──────────┘ │
└──────────────────────────────┘
```

**Принцип работы:**

1. Пользователь пишет код в редакторе CodeMirror (или выбирает пример из выпадающего списка) и нажимает «Запустить»
2. `api.js` отправляет код на `POST /trace`
3. Бэкенд валидирует код через AST-whitelist
4. `tracer.py` выполняет код с `sys.settrace` и собирает события трёх типов: `call` (вызов функции), `return` (возврат), `line` (шаг строки)
5. Массив шагов (`steps[]`) возвращается в браузер
6. В зависимости от выбранного режима воспроизводит либо `animator.js`, либо `flow-graph.js`

## Classic View

Классический пошаговый режим. Активируется кнопкой «Classic» в переключателе режимов.

**Что отображается:**

- **Панель кода** — подсветка синтаксиса, активная строка выделена жёлтым фоном.
- **Scope-блоки** — каждый вызов функции получает отдельный блок, переменные обновляются внутри него. Блоки выстраиваются в дерево вызовов.
- **Шарики (DataBall)** — при изменении переменной из текущей строки вылетает цветной шарик и приземляется в нужную ячейку scope-блока.
- **Console** — вывод `print()`, строки появляются по мере выполнения.
- **Управление** — кнопки «⏮ ◀ ▶ ▶▶ ⏭», скорость (Медленно / Нормально / Быстро / Очень быстро), клавиши ← →, Пробел.

**Состояния scope-блока:**

| Класс | Смысл |
|-------|-------|
| `.active` | Выполнение сейчас в этой функции |
| `.waiting` | Вызов сделан, ждёт возврата дочерней функции |
| `.done` | Функция завершена, показывает `ret: значение` |

## Flow Graph View

### Концепция

Экспериментальный режим. Активируется кнопкой «Flow Graph» в переключателе режимов.

Программа представляется как **блок-схема**: каждая операция — узел определённой формы, данные движутся сверху вниз в виде токенов.

```
ASSIGN(x=0) → LOOP(i:0→5) → COMPUTE(x=x+1) → PRINT(x) → Консоль
```

- **Узлы** — описывают действие (присваивание, вычисление, вывод, цикл, условие).
- **Токены** — капсулы с данными (`x = 5`), перемещающиеся по блок-схеме.
- **Данные текут** по стрелкам сверху вниз, трансформируясь на каждом шаге.

Граф строится из массива `steps[]` без изменений в бэкенде.

**Конвейер построения графа (flow-graph.js):**

```
steps[] + sourceCode
      ↓
  parseOps()           — определяет тип каждой операции
      ↓
  expandLoopBodyOps()  — разворачивает bodyOps в плоский список
      ↓
  buildNodes()         — позиционирует узлы на canvas (вертикальный поток)
      ↓
  buildEdges()         — строит стрелки между узлами
      ↓
  buildTokens()        — создаёт токены с маршрутами
      ↓
  renderFlowGraph()    — рисует DOM + SVG, сбрасывает Console Panel
      ↓
  startFlowAnimation() — запускает последовательную анимацию
```

---

### Визуальный язык

Каждый тип узла имеет уникальную форму — как в классических блок-схемах:

| Тип узла | Форма | Цвет |
|----------|-------|------|
| **Assignment** | Параллелограмм (SVG polygon) | Синий `#2D5CB8` |
| **Loop** | Шестиугольник (SVG polygon) | Бирюзовый `#06B6D4` |
| **Condition** | Ромб (SVG polygon) | Оранжевый `#B45309` |
| **Print** | Скруглённый прямоугольник | Зелёный `#176A42` |
| **Compute** | Скруглённый прямоугольник | Янтарный `#92400E` |

Все SVG-фигуры рисуются инлайн: `<polygon points="..."/>` внутри `.fg-node`. При подсветке (litNode) применяется `drop-shadow` фильтр к `polygon`, а не `box-shadow` к div-у.

---

### Поддерживаемые типы узлов

Узлы регистрируются через два объекта:

- `FG_NODE_TYPES` — метки и функции генерации label.
- `FG_COLORS` — цветовая схема (border, glow, pulse).

Чтобы добавить новый тип узла — достаточно добавить запись в оба объекта.

---

#### AssignmentNode

**Назначение:** простое присваивание значения переменной.

**Форма:** параллелограмм (скошены левая и правая стороны).

**Пример кода:**
```python
x = 5
```

**В графе:**
```
  /─────────────────\
 /   ASSIGN          \
/    x = 5            \
\────────────────────/
```

**Цвет:** синий (`#2D5CB8`).

Генерирует DataToken: `x = 5`.

---

#### ComputeNode

**Назначение:** бинарная арифметическая операция, где хотя бы один операнд — переменная.

**Форма:** скруглённый прямоугольник.

**Пример кода:**
```python
y = x + 2
x = x + 1
```

**Цвет:** янтарный (`#92400E`).

Токен трансформируется при прохождении через узел:
- **self-update** (`x = x + 1`): `x=5` → squish → `x=6` + amber glow.
- **rename** (`y = x + 2`): `x=5` исчезает, появляется `y=7`.

---

#### PrintNode

**Назначение:** вызов `print()` — транзитный узел перед Console Panel.

**Форма:** скруглённый прямоугольник.

**Цвет:** зелёный (`#176A42`).

После прохода через PrintNode токен летит вправо и растворяется в правой Console Panel. Строки вывода появляются в панели с анимацией fade-in.

---

#### LoopNode

**Назначение:** цикл `for VAR in range(N)`.

**Форма:** шестиугольник — шесть точек (срезанные углы), визуально отличает цикл от других узлов.

**Пример кода:**
```python
for i in range(3):
    print(i)
```

**Цвет:** бирюзовый (`#06B6D4`).

**Стрелки цикла:**

- **Обратная стрелка (back-arc):** от тела цикла → входит в LoopNode **слева** (пунктир, бирюзовый). Обозначает возврат на следующую итерацию.
- **Стрелка выхода (exit-arc):** выходит из LoopNode **справа** → первый узел после цикла. Помечена «Нет» (условие цикла не выполнено).

LoopNode показывает текущую итерацию в реальном времени:
```
i in range(5)
i = 3         ← обновляется при каждом шаге
```

**Два режима работы:**

1. **Тело = `print(i)`** — LoopNode генерирует N отдельных токенов (`i=0`, `i=1`, `i=2`), каждый идёт LOOP → PRINT → Console Panel. Консоль накапливает вывод.

2. **Тело = вычисление** (`x = x + 1`) — один токен от предыдущего AssignmentNode приходит в LOOP. LoopNode запускает N итераций: LOOP → COMPUTE (in-place transform) → snap back to LOOP → ... → после последней итерации продолжает COMPUTE → PRINT → Console Panel.

---

#### ConditionNode

**Назначение:** условие `if VAR OP OPERAND:`.

**Форма:** ромб (diamond) — центральная горизонталь = середина ромба.

**Пример кода:**
```python
x = 5
if x > 3:
    print(x)
```

**Цвет:** оранжевый (`#B45309`).

После прихода токена ConditionNode показывает результат:
- `TRUE` — зелёным цветом; токен продолжает движение к ветке TRUE.
- `FALSE` — красным цветом; токен растворяется (если нет else) или уходит в ветку FALSE.

**Ветви в блок-схеме:**

- **Да (TRUE):** зелёная стрелка → узел слева от центра (если внутри цикла) или ниже по вертикали.
- **Нет (FALSE):** красная стрелка → узел справа (внутри цикла) или ниже по вертикали.

**Поддерживаемые операторы:** `>`, `<`, `>=`, `<=`, `==`, `!=`

**Поведение:**

| Ситуация | Поведение токена |
|----------|-----------------|
| `if` без `else`, TRUE | Токен проходит через CONDITION → PRINT → Console Panel |
| `if` без `else`, FALSE | Токен растворяется на CONDITION; Console не обновляется |
| `if/else`, TRUE | Токен идёт по TRUE-ветке (зелёная) → PRINT → Console Panel |
| `if/else`, FALSE | Токен идёт по FALSE-ветке (красная) → PRINT → Console Panel |
| `if` внутри цикла, FALSE | Токен растворяется; следующая итерация начинает новый токен |

**Метки стрелок:** «Да» (зелёная) и «Нет» (красная) — вместо TRUE/FALSE.

---

#### ConditionNode с else (Y-split)

Когда у `if` есть `else`, граф строится с раздвоением — Y-split:

- TRUE-ветка — PrintNode **слева** от центра, ребро зелёного цвета с меткой «Да».
- FALSE-ветка — PrintNode **справа** от центра, ребро красного цвета с меткой «Нет».

**Пример кода:**
```python
x = 5
if x > 3:
    print(x)
else:
    print(0)
```

**Схема:**
```
                  Да ──→ PRINT(x)  ──┐
ASSIGN(x=5) → IF(x>3)                ├──→ Консоль
                  Нет ──→ PRINT(0) ──┘
```

### Layout Engine

Flow Graph v1.3.0 использует **вертикальный поток** (сверху вниз):

- **Основные узлы** выстраиваются вертикально с шагом `FG_GAP_Y = 52 px`.
- **Центр по X** — середина canvas; простые узлы выравниваются по центру.
- **Условный Y-split:** TRUE-узел уходит **влево** от центра (`centerX - FG_NODE_W - FG_BRANCH_X`), FALSE-узел уходит **вправо** (`centerX + FG_BRANCH_X`).
- **IF внутри цикла:** TRUE-ветка (тело цикла) также влево; FALSE-стрелка уходит вправо назад к LoopNode.
- **Цикл:** тело цикла смещается влево относительно LoopNode; обратная стрелка входит **слева** в шестиугольник, стрелка выхода выходит **справа**.

**Метки стрелок:**

| Стрелка | Метка | Цвет |
|---------|-------|------|
| LOOP → тело | Да | Бирюзовый |
| LOOP → post-loop (exit-arc) | Нет | Бирюзовый пунктир |
| IF → TRUE ветка | Да | Зелёный |
| IF → FALSE ветка | Нет | Красный |

### DataToken

DataToken — капсула с данными, перемещающаяся по блок-схеме.

**Формат отображения:**
```
x = 5
i = 2
y = 7
```

**Жизненный цикл:**

```
Появление у StartNode (fade-in + scale)
        ↓
Движение к следующему узлу (gsap.to left/top, ease: power2.inOut)
        ↓
Трансформация (если ComputeNode) или транзит
        ↓
Движение вправо за пределы canvas
        ↓
Растворение при входе в Console Panel (fade-out + scale)
→ строки появляются в правой панели
```

**`currentVar`** — мутируемое поле токена, хранящее имя переменной. Обновляется при каждой трансформации в ComputeNode.

**Трансформации:**

| Тип | Условие | Анимация |
|-----|---------|----------|
| **self-update** | `op.target === token.currentVar` | squish (scale 0.72) → смена текста → bounce back + amber glow |
| **rename** | другая переменная | текущий токен исчезает (scale 0.60, opacity 0), появляется новый |

### Console Panel

Начиная с v1.3.0, Console **не является узлом блок-схемы** — это отдельная панель справа от canvas.

**Расположение:**

```
┌──────────────────────────────┬──────────────┐
│                              │   Консоль    │
│       Блок-схема (canvas)    │              │
│                              │   print()    │
│                              │ ──────────── │
│                              │  5           │
│                              │  7           │
└──────────────────────────────┴──────────────┘
```

**Поведение:**

- Панель сбрасывается при каждом новом запуске.
- Токен летит вправо за пределы canvas и растворяется при входе в панель.
- Console Panel подсвечивается фиолетовым glow при прибытии каждого токена.
- Строки появляются с анимацией `fade-in + slide-in` слева направо.
- `revealConsole()` добавляет только новые строки (инкрементально), не перерисовывает существующие.

**Технически:** консольный узел (`type: 'console'`) сохраняется в `nodeMap` для работы `tracePath`, но его `x`-координата устанавливается за пределами canvas (`canvasW + 20`). DOM-элемент для него не создаётся; `fgNodeReg` хранит `{ el: null, node }`.

### Управление скоростью

В шапке Flow Graph View расположены три кнопки скорости:

| Кнопка | Множитель | Эффект |
|--------|-----------|--------|
| `0.5×` | 0.5 | Все анимации в 2 раза медленнее |
| `1×` | 1 | Нормальная скорость (по умолчанию) |
| `2×` | 2 | Все анимации в 2 раза быстрее |

**На что влияет скорость:**

- Движение токенов между узлами
- Трансформации токенов (squish, bounce, fade)
- Glow/pulse эффекты на узлах
- Паузы между итерациями цикла
- Паузы при вычислении условия
- Задержки перед стартом анимации
- Появление строк в Console Panel

**Реализация:** глобальная переменная `FG_SPEED = 1`. Все GSAP-duration обёрнуты в `dur(s) = s / FG_SPEED`, все setTimeout-delay — в `delMs(ms) = ms / FG_SPEED`. Нет магических чисел, разбросанных по коду — все тайминги определяются через эти хелперы.

### Поддерживаемые сценарии

Все сценарии проверены в Flow Graph режиме:

**Простое присваивание:**
```python
x = 5
print(x)
```
Граф: `ASSIGN(x=5) → PRINT(x)` → консоль: `5`

**Арифметика с двумя переменными:**
```python
x = 5
y = x + 2
print(y)
```
Граф: `ASSIGN(x=5) → COMPUTE(y=x+2) → PRINT(y)` → консоль: `7`

**Self-update переменной:**
```python
x = 5
x = x + 1
print(x)
```
Граф: `ASSIGN(x=5) → COMPUTE(x=x+1) → PRINT(x)` → консоль: `6`

**Цикл с выводом переменной цикла:**
```python
for i in range(3):
    print(i)
```
Граф: `LOOP(i:0→3) → PRINT(i)` → токены: `i=0`, `i=1`, `i=2` → консоль: `0`, `1`, `2`

**Цикл с накоплением (compute inside loop):**
```python
x = 0
for i in range(5):
    x = x + 1
print(x)
```
Граф: `ASSIGN(x=0) → LOOP(i:0→5) → COMPUTE(x=x+1) → PRINT(x)` → консоль: `5`

**Цикл с условием (for + if):**
```python
for i in range(5):
    if i > 2:
        print(i)
```
Граф: `LOOP(i:0→5) → CONDITION(i > 2) → PRINT(i)` → консоль: `3`, `4`

**Условие (TRUE):**
```python
x = 5
if x > 3:
    print(x)
```
Граф: `ASSIGN(x=5) → CONDITION(x > 3) → PRINT(x)` → консоль: `5`

**Условие (FALSE):**
```python
x = 2
if x > 3:
    print(x)
```
Граф: `ASSIGN(x=2) → CONDITION(x > 3)` — токен растворяется; консоль пуста

**Условие с else — TRUE:**
```python
x = 5
if x > 3:
    print(x)
else:
    print(0)
```
Граф: `ASSIGN(x=5) → CONDITION(x>3) → [Да] → PRINT(x)` → консоль: `5`

**Условие с else — FALSE:**
```python
x = 2
if x > 3:
    print(x)
else:
    print(0)
```
Граф: `ASSIGN(x=2) → CONDITION(x>3) → [Нет] → PRINT(0)` → консоль: `0`

### Flow Graph Status

**Реализовано:**

- ✓ AssignmentNode — параллелограмм
- ✓ ComputeNode — скруглённый прямоугольник, self-update / rename трансформации
- ✓ PrintNode — транзитный узел с анимацией вылета в Console Panel
- ✓ LoopNode — шестиугольник, back-arc (слева), exit-arc (справа)
- ✓ ConditionNode — ромб, TRUE/FALSE ветвление с метками Да/Нет
- ✓ ConditionNode + else — Y-split граф
- ✓ ConditionNode внутри LoopNode
- ✓ DataToken с анимацией движения, трансформации, растворения
- ✓ Вертикальный поток (сверху вниз)
- ✓ Подсветка текущей итерации на LoopNode
- ✓ Console Panel — отдельная правая панель (не узел блок-схемы)
- ✓ Управление скоростью анимации: 0.5×, 1×, 2×
- ✓ SVG-фигуры узлов (polygon inline SVG)
- ✓ Тёмная тема

**Планируется:**

- ConditionNode: `elif`, вложенные условия, `else` внутри цикла
- FunctionNode (`def` + вызов)
- Вложенные циклы
- ListNode (массивы, доступ по индексу, изменение элементов, цикл по списку)
- Несколько операций внутри тела цикла

### `tracer.py` — Трассировщик

Использует `sys.settrace` для перехвата выполнения Python-кода. Генерирует события трёх типов.

**События:**

| Событие | Когда | Ключевые поля |
|---------|-------|---------------|
| `call` | При вызове пользовательской функции | `scope_id`, `parent_id`, `scope_name`, `args`, `depth` |
| `return` | При возврате из функции | `scope_id`, `scope_name`, `return_value`, `depth` |
| `line` | Перед каждой строкой | `scope_id`, `scope_name`, `line`, `variables`, `output` |

**Ключевые особенности:**

- `<module>` frame пропускает события `call`/`return` — только `line`. Это позволяет не создавать scope-блок для глобального уровня через tracer (глобальный блок создаётся отдельно на фронтенде).
- Аргументы функции (`args`) заполняются **на первом `line`-событии** внутри функции, а не на `call` — потому что в Python 3.12 `frame.f_locals` пуст в момент события `call`. Tracer ретроактивно дополняет предыдущий `call`-шаг.
- `scope_id` — уникальный номер каждого вызова функции (инкрементируется с 1). `parent_id` — `scope_id` вызывающей функции (0 = глобальная область).
- `depth` — глубина стека вызовов в момент `call` (0 = вызван из глобального кода).
- Код выполняется в изолированном namespace только с разрешёнными встроенными функциями.
- `print()` перехватывается: вывод копится в `captured_output[]`.
- Лимит: **600 line-шагов**. `call`/`return` в счётчик не входят. При превышении `truncated: true`.
- После `exec()` добавляется синтетический финальный `line`-шаг с итоговым состоянием (если оно отличается от последнего записанного).

**Сериализация значений (`_serialize`):**
- `int`, `float`, `bool`, `None` → как есть
- `str` → обрезается до 200 символов
- `list`, `tuple` → до 30 элементов, рекурсия до глубины 3
- `dict` → до 15 ключей, ключи приводятся к `str`
- `set` → до 15 элементов, сортируется
- Всё остальное → `str(value)[:100]`

### `flow-graph.js` — движок Flow Graph

#### Константы


#### Регексы

```javascript
// Детектирует бинарную арифметику: "var = operand OP operand"
const BINARY_ASSIGN_RE = /^(\w+)\s*=\s*(\w+|\d+\.?\d*)\s*([-+*/])\s*(\w+|\d+\.?\d*)\s*$/;

// Детектирует цикл for-range: "for VAR in range(N):"
const FOR_RANGE_RE = /^for\s+(\w+)\s+in\s+range\s*\(\s*(\d+)\s*\):/;

// Детектирует if-условие: "if VAR_OR_NUM OP VAR_OR_NUM:"
const IF_COND_RE   = /^if\s+(\w+|\d+\.?\d*)\s*(>=|<=|!=|==|>|<)\s*(\w+|\d+\.?\d*)\s*:/;
```

| Функция | Описание |

| `startFlowAnimation(graph)` | Запускает последовательную цепочку токенов |

#### `parseOps` — детектирование типов операций

| Тип op | Как детектируется |
|--------|------------------|
| `assignment` | Переменная изменилась, строка — не бинарная арифметика с переменной, не loop var, не loop body |
| `compute` | Переменная изменилась + `BINARY_ASSIGN_RE` совпало + хотя бы один операнд — переменная |
| `loop` | Переменная — loop var (найдена через `FOR_RANGE_RE` в sourceLines). Emits один раз |
| `print` | Вырос буфер `output[]`. Если переменная — loop var → идёт в `loop.outputs`. Если нет → отдельный op |
| loop `bodyOp` | Переменная изменилась на строке тела цикла → собирается в `loop.bodyOps[].values` |
| loop `bodyCondition` | Строка тела цикла совпала с IF_COND_RE → записывается как `loop.bodyCondition` |
| `condition` | Pre-scan находит `if`-строки и связывает с `else:` по отступу |

## Технические решения

### Почему встроенный HTTP-сервер, а не FastAPI

pip недоступен в среде разработки (SOCKS-прокси блокирует установку пакетов). Бэкенд переписан на `http.server`, `json`, `os` — нулевые зависимости.

### Сдвиг sys.settrace (off-by-one)

`sys.settrace` даёт событие `line` **перед** выполнением строки. Снимок в шаге N содержит переменные, установленные строкой N-1.

- **Classic View** решает это через look-ahead: `scheduleNextStep` сравнивает `steps[N]` и `steps[N+1]`, запускает шарик от текущей строки, а панели обновляет при приземлении шарика.
- **Flow Graph** использует `prevLineIdx` (номер строки из предыдущего шага) для определения типа операции: `sourceLines[prevLineIdx - 1]` — это строка, которая **только что** выполнилась.

### Loop body detection в parseOps

Для корректного определения тела цикла `flow-graph.js` принимает **не-trim'd** исходные строки. `loopBodyLineNums` строится заранее:

```javascript
const forIndent = line.length - line.trimStart().length;
for (let j = i + 1; j < sourceLines.length; j++) {
  if (bl.length - bl.trimStart().length > forIndent) loopBodyLineNums.add(j + 1);
  else break;
}
```

### expandLoopBodyOps — плоский граф из вложенной структуры

`buildNodes` работает с плоским массивом. `expandLoopBodyOps` превращает:

```
[assign, loop{bodyOps:[compute]}, print]
```
в:
```
[assign, loop, compute, print]
```

не копируя объекты — только расставляя ссылки. `opToNodeId = new Map(node._op → node.id)` работает через идентичность ссылок.

### Console Panel — виртуальный console node

`revealConsole` больше не ищет DOM-элемент в canvas. Вместо этого:
1. `buildNodes` создаёт console node как логический объект.
2. `renderFlowGraph` устанавливает его `x = canvasW + 20` (за пределами canvas).
3. `fgNodeReg.set(consoleId, { el: null, node })` — без DOM-элемента.
4. `revealConsole` напрямую пишет в `document.getElementById('fg-console-output')`.
5. `litNode` при `entry.el === null` светит border у `#fg-console-panel`.
6. Токен перемещается на позицию `tokenLeft(consoleNode)`, пересекает правую границу canvas и растворяется в панели (canvas имеет `overflow: visible`).

### FG_SPEED — централизованные тайминги

Все GSAP duration и setTimeout delay обёрнуты в `dur(s)` и `delMs(ms)`. Нет рассыпанных магических чисел. Смена скорости применяется к следующей анимации мгновенно (старые tweens не перерисовываются).

### Пустые аргументы на call-событии (Python 3.12)

В Python 3.12 `frame.f_locals` возвращает пустой словарь в момент события `call`. Tracer откладывает заполнение `args` до первого `line`-события внутри функции и ретроактивно дополняет предыдущий `call`-шаг.

### Центрированное дерево — почему depth+1

Функции начинаются с `y = (depth+1) * 165 + 16`, то есть со строки 1, а глобальный блок — строка 0. Они никогда не пересекаются по y, функции свободно расходятся влево и вправо.

### Ghost-якорь консоли

Цель шарика для Console (Classic View) — `#console-anchor`, нулевой div в конце `#console-body`. `innerHTML = ''` уничтожает его, поэтому хранится JS-ссылка и все функции очистки восстанавливают его через `consoleBody.appendChild(consoleAnchor)`.

## Release Notes

### v1.3.0

**Flow Graph — полная переработка визуального движка**

- **Новая система блок-схем:** каждый тип узла теперь имеет собственную форму:
  - AssignmentNode → **параллелограмм** (SVG polygon)
  - LoopNode → **шестиугольник** (SVG polygon)
  - ConditionNode → **ромб** (SVG polygon)
  - Print / Compute → скруглённый прямоугольник

- **Новая компоновка (Layout Engine):** поток сверху вниз вместо горизонтального ряда.
  - Цикл: обратная стрелка входит в LoopNode **слева**, выходная стрелка (exit-arc) выходит **справа** с меткой «Нет».
  - Условие: TRUE-ветка уходит **влево**, FALSE-ветка — **вправо**. Метки «Да» / «Нет» (вместо TRUE/FALSE).
  - Условие внутри цикла: тело цикла (TRUE) — левая колонка, FALSE-стрелка возвращается на LoopNode.

- **Отдельная Console Panel:** вывод `print()` вынесен из canvas в правую панель «Консоль».
  - Токен летит вправо за пределы canvas и растворяется в панели.
  - Console Panel подсвечивается при прибытии каждого токена.
  - Панель сбрасывается при каждом новом запуске.

- **Управление скоростью анимации:** кнопки 0.5×, 1×, 2× в шапке Flow Graph.
  - Скорость влияет на движение токенов, glow/pulse, fade, задержки, паузы между итерациями.
  - Реализовано через `FG_SPEED` и хелперы `dur()` / `delMs()` — нет магических чисел.

- **Добавлены и улучшены сценарии:**
  - `for + if` — условие внутри цикла с правильным ветвлением
  - `if / else` — Y-split граф с двумя ветками
  - Цикл с вычислением — `x = x + 1` внутри `for`

- Classic View не затронут. Бэкенд не изменён. 24/24 теста проходят.
